# Using ax-shell — operations, configuration and local packaging

**Status:** host-bound operations reference (owner's machine, macOS 26) · 2026-10-26  
**Scope:** what the shipped macOS platform crate really does today, how to build/run/classify it on the owner's host, the exact config-file contract, and how to assemble the local `.app` bundle. Windows is not implemented; nothing here claims parity.

## Build conventions (do not deviate without an owner decision)

- Toolchain is **pinned**: Homebrew `rustc 1.98.1` (local) and CI both use 1.98.1, because 1.99.x's rustfmt lays out `objc_msg!` macro arguments differently — the pin keeps local and CI byte-identical. Bump the pin together on both sides (`.github/workflows/ci.yml`).
- Build/test command shape: `MACOSX_DEPLOYMENT_TARGET=26.0 cargo build --manifest-path crates/platform-macos/Cargo.toml --release --bin ax-shell`. All commands below assume this env var; the deployment target 26.0 also becomes the bundle's `LSMinimumSystemVersion`.
- The platform crate is deliberately **not** a workspace member (it links Apple frameworks and must stay buildable per-crate); its target dir is `crates/platform-macos/`, not the repo root's.
- Checklist before claiming anything: `cargo fmt --check`, clippy `-D warnings` (crate `--all-targets` and workspace), `cargo test --lib` (platform, 50 tests) and `cargo test --workspace` (27 tests).

## Run modes

| invocation | what runs | exit codes | end state on disk |
|---|---|---|---|
| `ax-shell` | the menu-bar shell itself (NSStatusItem) until Quit | 0 on clean quit | whatever Save wrote (a real config) |
| `ax-shell --self-test` | full in-app exercise: classification gate, reflow probe on the registered fixture, rules rounds, panel + row-based rules editor, restore | 0 pass · 1 failure/restore-failure · 2 skipped (pre-run config invalid/unsafe) | restored to the pre-run state; a no-file start returns to no-file |
| `ax-shell --panel-click-proof` | Save driven through the **button's real click dispatch** (`performClick:`) with a rule row first empty (refused) then filled (saved) | 0 pass · 1 proof failure · 2 skipped (pre-existing config file refused untouched) | no-file runs remove the file they created; pre-existing files are byte-exact untouched |
| `ax-shell --reset-defaults` | writes the default config (also 0600) | 0 ok · 1 error | a config file exists |

Guard semantics for the evidence modes (both mirror the standing decisions): a pre-existing config file is a real owner profile — skipped fail-closed, never read/written; runs without a file may create one and must remove it again; a failed removal fails the mode, never looks successful.

## Config file contract — `~/.hypr-rust/config.json`

Single-owner file. Hard rules, re-validated at every run (no file → defaults apply in memory; nothing is written at startup):

- **Front-of-file safety (fail closed):** the file must be a regular file; a **symlink is rejected** before any load or write (`config is a symlink`); the mode must be **owner-only 0600 with matching uid** (`not owner-only (mode NNN)` otherwise) — enforced by `symlink_metadata` classification, probed in audit log Jalur K + ARENA-VERIFICATION.
- Fields (canonical save format, regenerated by the app — the file always validates before it can be written through Save):

| field | type / values | notes |
|---|---|---|
| `version` | `1` exactly | only schema version 1 parses |
| `layout` | `"master-stack"` or `"columns"` | `parse_kind` single name table |
| `outer_gap`, `inner_gap` | finite number ≥ 0 | panel fields |
| `master_ratio` | finite number in **0.05–0.95** | out-of-range is refused (`config value out of range: master_ratio`) |
| `auto_tiling` | bool | default **false**; tiling runs only on the explicit `Reflow:` menu command — never auto until an owner decision changes this |
| `include_dialogs` | bool | default false; dialog/floating subroles stay excluded unless allowed by a rule's policy |
| `rules` | array of rule objects | see below |

- Rule object: `{"bundle": "…", "pid": N, "dialogs": "…"}` — each field optional, **at least one matcher (`bundle` or `pid`) required** so a rule can never silently match every app; `bundle` must be a non-empty string without `"` or `\`; `pid` must be an integral number in 0…u32::MAX (huge values are rejected, not saturated); `dialogs` ∈ `include` / `exclude` / `default`; **unknown fields are ignored** (newer configs readable by older builds).
- `dialogs` policy meaning the same as the panel: `include` lets the policy treat that app's dialogs as regular windows, `exclude` keeps them out even when dialogs are globally included, `default` follows the `include_dialogs` switch. **App protection (ADR-0006): a rule whose policy is `exclude` also removes that app's normal windows from the reflow targets** — that is how an owner shields an app; mandatory exclusions (own/system/desktop windows) stay non-overridable no matter what a rule says.

## Settings panel (what the menu exposes)

Menu: status line → `Reflow: master-stack` (or columns) / `Pause` / settings summary / `Settings…` / `Reset to defaults` / Accessibility status / `Diagnostics` / `Quit`.

**What `Reflow:` touches ([ADR-0006](./adr/0006-real-window-reflow-strict-no-partial.md)):** the menu command can be triggered two ways — a menu click or the **global hotkey ⌃⌥⌘R** ([ADR-0007](./adr/0007-global-hotkey-reflow.md); registered once at shell startup, same action and same status line either way; if another app already owns that chord the shell logs `hotkey: not registered — …` and keeps working through the menu, and while ax-shell runs the chord is consumed system-wide before other apps see it) — and it is the **real-window** surface — it enumerates every regular app and targets its **normal windows** on the main display (minimized, fullscreen-looking and off-display windows are skipped and counted in the status line; dialogs follow `include_dialogs` + rules; own/system/desktop windows are always excluded and rules can protect an app via `exclude`). Application runs **strict no-partial**: all frames are read before the first write (a **target** read failure refuses with **0 windows touched**; an app-level enumeration failure is retried once and, if it persists, skipped with its pid named — `unavailable skipped: pid …`, ADR-0006 §2.1 amendment 2026-10-27, because the first real-window run showed busy apps timing out transiently with `-25204`), each window is written with the verified single-window contract, a failure restores every changed window, and an unverifiable restore is reported as a **loud `PARTIAL STATE` status naming the observed frames** — never as success, never as "atomic". The status chip always says which of the three happened: `tiled N window(s)`, `refused … (all windows restored / 0 windows touched)`, or `PARTIAL STATE …`; a clean refusal also names the failing window by app pid (`failed at app pid N (window i)`) so an app that clamps its window size can be identified from the log and protected with a `exclude` rule. **Why a refusal happens in practice:** macOS clamps every window to its app's minimum size (observed 2026-10-27: Nicegram Desktop 628pt high, Finder 511×252, Firefox 500 wide) — when a stack/column slot is smaller than that minimum the read-back mismatches and the whole batch rolls back cleanly. Remedies: give the app an `exclude` rule, change to a layout whose slots fit, or reduce the window count; a rule can always be flipped back to `include` (Finder tiled fine in `monocle`/`bsp` while being refused in `columns`). Auto-tiling stays off; quit leaves windows where they last landed. **Automated evidence (`--self-test`, `--panel-click-proof`) never reaches this path** — those keep the fixture-bound reflow.

The panel opens through `show_settings`, prefills from the effective config, and Save re-validates everything through `Config::from_json`. Current editor shape is **one row per rule** (`NSComboBox` bundle entry seeded from running apps' `bundleIdentifier`s — ids only, no titles; policy popup include/exclude/default; per-row remove by pointer identity; an Add-rule button). A pid rule shows read-only as `pid N (from file)` because pid rules can only arrive via the JSON file. Save regenerates only the canonical JSON from the rows (they are the entry surface — raw row text never reaches the file body); an empty row (no matcher) is refused by the same validation as a file load. Two feedback rules (hardening 2026-10-26, owner first-run finding): the three number fields are checked **per field before the body is built** — a comma decimal separator or stray characters get `invalid number in <field>: "…" (use digits and a dot, e.g. 0.35)` instead of a generic JSON error — and **every save outcome appears in the panel itself** (status line at the top of the panel) as well as on the menu chip, so nothing depends on opening the menu to see what happened. Evidence: ARENA-VERIFICATION Paths K (panel), L (click-path), M (rows), panel-click-proof rounds incl. the comma round.

Quit leaves every window at its last OS-accepted position; nothing is restored on next start.

## Logs

`~/.hypr-rust/shell.log` — append-only, best-effort (dropped lines are a real failure mode when the directory is unavailable, not silently fatal). Contents include self-test/proof traces, settings save statuses and reflow results. Keep titles and secrets out of anything you paste from it; fixture pids and `com.example.*` ids are safe.

## Fixture harness (evidence runs)

`spikes/macos/spike-macos spawn-target [--count n] [--dialog]` starts self-owned fixture window(s) and registers the pid in `~/.hypr-rust/fixture-target.json` (the self-test rounds are fixture-bound; the interactive menu `Reflow:` command is the real-window path per ADR-0006). The planner's own-app/system/dialog classification is mandatory and cannot be overridden by rules.

## Local packaging — `scripts/package-macos.sh`

Assembles `crates/platform-macos/target/dist/ax-shell.app` from a fresh release build:

- bundle: `Contents/MacOS/ax-shell` + `Contents/Info.plist`; `CFBundleIdentifier io.github.niumination.ax-shell`, `LSUIElement` (menu accessory), version read from the crate manifest, `LSMinimumSystemVersion` = the deployment target (26.0).
- validated by `plutil -lint` in the script; **ad-hoc signed only** (`codesign --force --sign -`).
- CI runs this on `macos-26` and attaches the bundle as the `ax-shell-macos-app` artifact.
- Run it directly (`open crates/platform-macos/target/dist/ax-shell.app`) or via the binary path.

Honest limits of this packaging slice — read before describing it to anyone:

1. **Not a release artifact.** No Apple Developer identity, no signing/notarization, no DMG; the PRD gates beta/release distribution on a proven signing plan.
2. **No distribution claims for this host.** The owner's machine is non-Apple hardware; USER-DEVICE-PROFILE §5 keeps distribution/support positioning an open legal/product question.
3. **AX trust under the bundled identity is runtime-tested** (ARENA-VERIFICATION Path N): attribution is per launch identity — direct-exec from a shell inherits the CLI-era grant, while a LaunchServices launch of the bundle (`open`) is **denied** until this exact bundle is added in System Settings → Privacy & Security → Accessibility (a manual GUI step; macOS never prompts for AX on its own). With `denied`, every reflow/AX path reports `permission denied` and touches nothing (fail-closed, proven pre-grant); after the owner granted the dist bundle, the same launch reported `granted` and the fixture reflow applied (`applied 2 window(s)`). After any rebuild or path change of the bundle, **remove and re-add** the entry in System Settings → Privacy & Security → Accessibility (a toggle alone is not enough — TCC keeps the signature it recorded at add time, and the ad-hoc cdhash changes on every build; owner-confirmed 2026-10-26) before claiming AX; re-verify with `open <app> --args --self-test` and the log's `self-test: exit` line.
4. **macOS floor is 26,** matching the pinned build; the PRD floor of Ventura 13 is not met by these builds and is not claimed.
5. No icon yet; the app name/bundle id defaults were chosen as the neutral crate identity and are overridable via env.
6. Windows packaging: nothing — the Windows adapter is not implemented and nothing Windows-side is validated.
